# 概述

局部有雨（Localized Rain）把原版「整个维度共用一份天气」改为按生物群系范围独立判定。安装后，同一维度内可以同时存在晴天、降雨与雷暴：沙漠晴空，相邻的森林正在下雨，远处的海洋处于雷暴。

天气以「3D 生物群系片」为单位。每个 16×16 方块的水平列沿高度采样生物群系，相邻列中相同且高度相接的生物群系段合并为一个连通范围，范围内所有位置共享同一份天气。连成一片的同种生物群系共享天气，被地形隔断的同种生物群系各自独立，洞穴、浮岛与地表的生物群系也分别判定。

模组支持 Minecraft 1.21.1 与 NeoForge 21.1.265 及以上版本，当前版本为 1.0.0-preview。服务端与客户端都需要安装，单人游戏与多人服务器均可使用，许可为 MIT。

# 安装

1. 安装 NeoForge 21.1.265 或更高版本（Minecraft 1.21.1）。
2. 将 localizedrain-1.0.0-preview.jar 放入 mods 文件夹，服务端与客户端都需要放置。
3. 启动一次游戏，生成 config/localizedrain-common.toml 后按需修改。

# 功能

## 按 3D 生物群系片判定天气

- 每个 16×16 方块的水平列按 quart（4 方块）采样出竖直方向的生物群系段，水平相邻且 Y 区间相接的同种段合并为同一片。
- 同一片内的所有位置共享天气，片与片之间的边界跟随生物群系轮廓，不依赖地表高度或生物群系子状态后缀。
- 同种但互不相连的生物群系可以拥有不同天气。两片被山脉隔开的森林，可以一片下雨、一片晴朗。
- 洞穴生物群系、浮岛群系、下界与末地的立体生物群系同样按 3D 连通范围划分。
- 天气类型、剩余时长、雨量与雷量都写入存档，退出重进后状态保持。
- 水平分辨率为 16 方块，垂直分辨率为 4 方块。

## 天气推进与性能

- 服务端推进所有已加载区块对应的片；未加载区域的片冻结、状态保留，重新加载后继续。
- 默认每 20 tick（1 秒）扫描一次，每次把每片推进 20 tick，天气总时长与渐变速度不随扫描间隔改变。
- 扫描受每 tick 预算限制：默认最多新扫描 4 列，另有 2ms 时间预算，超出部分留到后续 tick。玩家所在列不受预算限制，进入新区域时不会短暂按晴天处理。
- 关闭 scan3dSubstates 后只推进每列地表所在的段，用于在极端情况下降低开销。
- 下界、末地等无天光维度默认晴天，通过命令或 API 设置的天气会按设定时长生效。
- 长期未推进的状态按天数与条数上限清理，默认保留 7 天、每维度最多 4096 片。

## 局部化的原版效果

- 降雨与雷暴强度、天空亮度、亡灵燃烧、雷暴刷怪、炼药锅集水与积雪按实体所在片判定。
- 雷暴片按原版概率单独生成闪电，晴天片不会落雷。
- 客户端雨雪粒子、雨声与雾按玩家所在片渲染，跨片时按原版 0.01/tick 的速率过渡，约 5 秒完成。
- 安装 Xaero's Minimap 后，天气信息行显示玩家所在片的天气，并在跨片时立即切换。

## 手动天气

- 命令与 API 的手动设置在计时内覆盖白名单与黑名单，到期后回到晴天，再由名单决定是否重新进入自然循环。
- 手动状态使用独立计时器，不参与自然随机翻转。
- 被 weatherBiomeOverrides 锁定（包括强制晴天）的片不会被手动设置修改，命令会提示被跳过的片数。

# 命令

需要权限等级 2。

```
/weather clear|rain|thunder [duration]
/weather clear|rain|thunder at <pos> [duration]
/weather clear|rain|thunder area <from> <to> [duration]
/weather clear|rain|thunder global [duration]
/weather type <id> [duration|at <pos>|area <from> <to>|global]
```

| 范围写法 | 作用对象 |
| --- | --- |
| 不写范围 | 执行者所在的群系片 |
| at <pos> | 指定坐标所在的群系片，按该坐标的实际高度判定 |
| area <from> <to> | 覆盖范围内的片，水平方向每 128 方块采样一次 |
| global | 当前维度所有已记录天气的片 |

- duration 的单位为 tick，省略时使用该天气类型的默认随机时长。
- 原版 /weather 指令由本模组接管，不写范围时只影响执行者所在片；需要影响整个维度时使用 global。
- area 单次最多检查 512 个采样点、覆盖 64 片，并最多触发 8 次列扫描。超出上限时会提示缩小范围，或先在该区域执行 /weather at 完成列扫描。
- /weather type <id> 使用 localizedrain:weather_type 注册表中的类型 id，支持 Tab 补全。内置的 clear、rain、thunder 是三个内置类型的快捷写法。

# 配置

配置文件位于 config/localizedrain-common.toml，由服务端读取。

## 天气时长

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| minClearTicks / maxClearTicks | 12000 / 168000 | 晴天持续时间范围（tick） |
| minRainTicks / maxRainTicks | 12000 / 24000 | 降雨持续时间范围（tick） |
| minThunderDelayTicks / maxThunderDelayTicks | 12000 / 180000 | 降雨后出现雷暴的等待时间范围（tick） |
| minThunderTicks / maxThunderTicks | 3600 / 15600 | 雷暴持续时间范围（tick） |

## 性能与存档

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| weatherSimulationIntervalTicks | 20 | 已加载区块的扫描间隔，范围 1–200 |
| scan3dSubstates | true | 是否推进整列的所有群系段 |
| maxColumnScansPerTick | 4 | 每 tick 新扫描的列数上限，范围 1–64 |
| stateRetentionDays | 7 | 未推进状态的保留天数，0 表示不按时间清理 |
| maxStoredStates | 4096 | 每维度天气状态条数上限，范围 256–65536 |
| maxParentEntries | 16384 | 每维度并查集父表上限，范围 4096–1000000 |
| debugLogging | false | 输出列扫描、分量合并与玩家所在片的诊断日志 |

## 过滤规则

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| weatherBiomeWhitelist | 空 | 命中群系的天气池：只会出现列出的天气；空 = 默认自然池 |
| weatherBiomeBlacklist | 空 | 从命中群系的天气池中剔除列出的天气，其余天气照常循环 |
| weatherBiomeOverrides | 空 | 强制命中群系固定为一种天气，优先级最高 |

## 写法

三条名单都使用「生物群系选择器=天气」：

- minecraft:desert：精确匹配单个生物群系。
- minecraft:*：匹配整个命名空间。
- #minecraft:is_ocean：匹配生物群系标签（服务器启动/配置重载时解析）。

天气部分可以写类型 id（如 examplemod:sandstorm）、短名 clear/rain/thunder，
或天气类型标签 #localizedrain:dry（标签只在白名单/黑名单里有效，强制天气必须写具体类型）。

## 规则优先级与语义

强制天气 > 黑名单 > 白名单 > 默认自然池。

- 强制天气：命中的群系永远只有这一种天气；同一群系多条命中时按配置顺序取第一条。强制晴天是真正锁定，命令与 API 也无法在该群系制造天气。
- 白名单：命中的群系只在列出的天气里循环（同一群系可以写多条）。
- 黑名单：命中的群系排除列出的天气，但仍会在剩余天气里循环；同时命中白名单时，从白名单池里剔除。
- 默认自然池：没有显式白名单的群系使用 #localizedrain:natural 标签；本模组不内置标签文件，标签不存在时回退到内置晴/雨/雷。
- 干燥群系（Biome#hasPrecipitation() == false，例如原版下界/末地群系）在没有显式白名单时，会自动剔除会降水或会打雷的类型，因此默认永远是晴天。
- 若某个群系可抽到的天气只剩晴天（例如白名单只写晴天，或黑名单剔除了全部天气），视为锁定晴天，不创建天气状态。

## 写法示例

```toml
weatherBiomeWhitelist = [
  "minecraft:plains=clear",
  "minecraft:plains=localizedrain:rain"
]

weatherBiomeBlacklist = [
  "minecraft:desert=localizedrain:rain"
]

weatherBiomeOverrides = [
  "minecraft:ice_spikes=clear",
  "#minecraft:is_ocean=localizedrain:thunder"
]
```

强制天气的类型 id 在判定时解析，因此可以直接填写附属模组注册的类型。

# 兼容性

- Xaero's Minimap：可选联动。安装后天气信息行显示玩家所在片的天气并立即切换，未安装时不加载相关类，也不作为前置。
- 附属模组：可以在 localizedrain:weather_type 注册表注册天气类型，通过 WeatherApi 查询或设置。服务端的降雨、降水、雷暴与天空亮度判定都按天气类型工作。
- 原版全局天气接口：其他模组调用 ServerLevel#setWeatherParameters 时，会转换为当前维度已记录的片一起变天。
- 本模组不添加物品、方块与维度，只修改天气系统。

# 已知限制

- 客户端雨雪粒子、雨声、雾与天空亮度按玩家所在片的雨量渲染，不做逐方块局部化。原版只有一条围绕相机的雨柱，跨片时通过约 5 秒的渐变过渡。
- 水平分辨率为 16 方块、垂直分辨率为 4 方块，更薄或更窄的生物群系夹层会被量化到相邻段。
- 列扫描按区块中心列采样，一列内的生物群系变化以中心为准。
- 玩家所在列不受扫描预算限制，首次进入完全未探索的区域时会有一次完整的列扫描开销。
- 未加载区域的天气冻结，从未被扫描到的片按晴天处理。
- 被清理机制删除的片不保留天气记忆，重新加载后从新的晴天周期开始。
- 默认 1 秒的扫描间隔使天气切换最多延迟 1 秒生效。
- 0.4.x 及更早版本的存档 key（p:、g: 与 |biome 子状态）在载入时丢弃，不迁移旧天气状态。
- 自定义天气类型只有服务端天气语义，粒子、音效与雾效需要附属模组自行渲染。
